## Code documentation (docwizz)

`docs/` is generated by [docwizz](https://github.com/mycaravam-crypto/docwizz) from the code itself: structure,
dependencies, request flows, documentation gaps and architecture findings. Use it to find your way before you
explore the code file by file.

**Before exploring the code, read:**

1. `docs/index.md`: the stack, building blocks, coverage and links to everything else.
2. `docs/architecture.md`: the layers, which layer may depend on which, violations and cycles.
3. `docs/api.md`: every endpoint with its route, input, response, handler (`file:line`) and frontend callers.
4. `docs/modules/<module>.md` for the folders you will touch. The name is the folder path with `/` replaced by `-`
   (`backend/Application` → `docs/modules/backend-Application.md`). Each page lists the module's components, the
   request flows through it (endpoint → … → database or external system), its documentation gaps and its dependencies.

`docs/views/` has the system context, containers, data model, deployment and packages. `docs/quality.md` lists the
documentation gaps by priority.

**For one symbol, file, folder or endpoint**, ask docwizz for just the facts that matter, within a token budget:

```bash
docwizz context . --for "POST /api/orders" --budget 4000   # or a qualified name, a file, a folder
```

It lists the target, its callers and callees, the request flows through it, tests, gaps and the files to read first,
each line marked with its provenance. If it says the model is stale, run `docwizz generate .` first. If your agent
supports MCP, `docwizz mcp .` serves the same facts as tools (`find_symbol`, `context`, `callers`, `trace_endpoint`,
`impact`, `check`, ...).

**Weigh what you read by where it comes from:**

- *Detected* facts (no marker) are read from the code: signatures, calls, routes, injections.
- *Inferred* facts are marked `(inferred)`. They come from heuristics (a database behind a repository, the purpose of
  an external URL). Confirm them in the code before you rely on them.
- 🤖 marks an AI draft. It is a draft, not a fact: never treat it as a statement about the code.
- Text a human wrote (doc comments) can be outdated; `docs/quality.md` flags docs that contradict the code.

**docwizz is for navigation, not a substitute for the code.** Before you change a file, read the real code. The
`file:line` links in the docs tell you where to start.

**Definition of done for a change:**

```bash
docwizz check . --since <base-branch> --format json   # no new gaps, violations or contradictions ("pass": true)
docwizz diff . <base-branch>                          # changed symbols, affected pages, linked tests: review them
docwizz generate .                                    # refresh docs/ so the next task doesn't read a stale model
```

`docs/index.md` names the commit the docs were generated from. If it isn't the commit you are working on, run
`docwizz generate .` first. Generated pages start with `<!-- generated by docwizz -->`: never edit them by hand, your
edits are overwritten. Write documentation into the code (doc comments) or into `docs/architecture/`.
